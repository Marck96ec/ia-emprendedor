# Reporte de regresión

| Caso | Cobertura |
|---|---|
| 1. Canal inexistente | Prueba determinística de bloqueo incluso si se omite el canal en el contrato. |
| 2. Alternativa de canal | WhatsApp y contactos disponibles permiten ejecutar sin redes. |
| 3. Oferta anterior | Reutilización del resultado declarado y rechazo de reconstrucción sin evidencia. |
| 4. Acción pendiente | Continuación con relación y motivo conocido o no informado. |
| 5. Acción bloqueada | El canal ausente y la delegación inviable siguen bloqueados. Se rechaza una referencia inexistente. |
| 6. Hipótesis sin evidencia | Transición a inconclusa con percepción conservada. La evidencia cualitativa concreta sigue admitida. |
| 7. Memoria histórica | Snapshot PostgreSQL y contexto en semanas 5 y 8. |
| 8. Restricción resuelta | Cambio sobre el mismo recurso, enlace de procedencia y snapshot histórico conservado. |
| 9. Personalización transversal | Comparación con el proveedor real sobre mantenimiento y limpieza, con objetivos, canales y capacidad distintos. |
| 10. Recurrencia | Flujo de caja en período nuevo permitido y período repetido rechazado. |
| 11. Duplicado semántico | Oferta principal y propuesta de valor de la misma intención se comparan con el historial. |
| 12. Entregable de cobro | La capacidad de mensajes reemplaza fichas de ofertas para cobros. La aprobación exige el formato esperado. |
| 13. Seguridad | Dos propietarios locales. Rechazo de lectura/escritura ajena y de modificación directa; aviso de dependencia antes del resultado. |

La primera corrida de los nuevos tests se inició antes de implementar y falló porque la evaluación de hipótesis no existía. La reproducción ejecutable de la referencia se registró después con código cargado del merge previo, además de las comparaciones con IA.
