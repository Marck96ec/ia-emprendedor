# Deterministic Regression Analysis — TuCEO IA v2.7

**Date:** 2026-11-26
**Branch:** feature/strategic-intelligence-v2

---

## Purpose

This document identifies which plan fields are verifiably deterministic (computable by TypeScript without AI reasoning), which are partially deterministic (TypeScript can derive a value, but AI judgment may be more accurate), and which gaps remain in deterministic validation.

---

## 100% Deterministic Fields (Safe to Extract)

### `time_allocation.*`

**Evidence:** Lines 587–603 of `generate-ceo-plan.ts`. After every successful generation, these three values are overwritten unconditionally:

```typescript
{
  ...businessRules.data,
  time_allocation: {
    ...businessRules.data.time_allocation,
    available_hours: input.diagnostic.ownerHoursPerWeek,       // always from diagnostic
    allocated_hours: allocatedHours,                            // always sum of estimated_hours
    reserved_hours: input.diagnostic.ownerHoursPerWeek - allocatedHours,  // always available - allocated
  },
}
```

There is no code path where the AI-generated `time_allocation` is used. The AI generating these fields is a token waste and a potential source of hallucination.

**Recommendation:** In Phase 2, make `time_allocation.*` optional in the AI model schema (`StrategicCEOPlanModelSchema`) and always compute them in TypeScript. This reduces prompt token pressure and eliminates a class of potential structural validation errors.

**Risk:** Low. No downstream code reads the AI-generated value before it's overwritten.

### `diagnosis` (legacy text field)

**Evidence:** Line 605: `diagnosis: businessRules.data.strategic_diagnosis.diagnosis.summary`. Always derived from the structured field. The AI-generated top-level `diagnosis` string is ignored.

**Recommendation:** Remove from AI output contract in Phase 2. Compute from `strategic_diagnosis.diagnosis.summary`.

## Partially Deterministic Fields (Repair Pattern)

These fields are generated by the AI and then verified/corrected by TypeScript. The AI value is used as the starting point.

### `strategy.work_key`

**Derivation:** `inferWorkKey(action.title)` — stem-based lookup of known work_key patterns from the action title.

**Gap:** The inference is based on title keywords. When the AI generates an ambiguous title (e.g., "Revisar los resultados de la semana"), `inferWorkKey` may return `"other"` while the AI's business context would correctly classify it as `"operations_measure"`.

**Current behavior:** `normalizeActionStrategy` in `repairPlanMetadata` calls `inferWorkKey` and overrides the AI value only when `inferWorkKey` returns a different non-other value.

**Recommendation:** Keep AI as primary. Use `inferWorkKey` as a fallback and correction only. Monitor `repairsApplied` for `action.N.work_key` to detect systematic AI failures.

### `strategy.intent`

**Derivation:** `inferredIntent(action.title)` — partial match on action_type context.

**Gap:** Intent can only be fully inferred for `ai_assisted` and `build` patterns. For other cases, the AI's understanding of business progression (discover → validate → execute → optimize) is richer than any title-based heuristic.

**Current behavior:** `normalizeActionStrategy` applies `inferredIntent` to override specific cases (e.g., `ai_assisted` always maps to `execute` or `build`).

**Recommendation:** Keep as-is.

### `strategy.deliverable`

**Derivation:** `commercialDeliverableFor(action.title, strategy)` — keyword-based classification of whether a commercial action produces `commercial_offers` or `commercial_messages`.

**Gap:** The title "Crear dos mensajes de cobro para saldos pendientes" correctly maps to `commercial_messages` via keyword detection. But a novel phrasing could evade the keyword list.

**Current behavior:** `validateActionDeliverable` and `commercialDeliverableFor` are deterministic. `repairPlanMetadata` corrects the AI via `normalizeActionStrategy`.

**Recommendation:** Keep as-is. The keyword list is well-maintained and covers known cases.

## `sameWork` Word-Overlap Gap

The `sameWork()` function in `src/lib/strategic-action.ts` detects semantic equivalence between actions using word-stem overlap (threshold: 0.67 for min-side, 0.5 for max-side).

**Gap:** The AI can evade `sameWork` by using entirely different words for semantically identical work:

| Prior action | New action | Overlap | Blocked? |
|-------------|------------|---------|----------|
| "Contactar propietarios de talleres mecánicos" | "Visitar negocios de reparación automotriz" | 0.0 | ❌ No |
| "Contactar propietarios de talleres mecánicos" | "Presentar el servicio a propietarios de talleres del norte" | 1.0 | ✅ Yes |

The synonyms `taller mecánico` / `reparación automotriz` and `inventario` / `stock` share no stems after normalization. This gap requires semantic similarity beyond word-stem overlap to detect.

**Current mitigation:** The CONTRATO prompt instructs the AI to use the same `work_key` for recurring work, and `sameWork` checks `work_key` identity for fast-path detection before word overlap. This covers the most common cases but not the full substitution scenario.

**Non-solution for now:** Embedding-based similarity would require an additional provider call or a local embedding model. This is documented as a known gap, not patched in this phase.

## `repairPlanMetadata` Repair Frequency Signal

The `repairsApplied` array in CEO_PLAN_TRACE indicates how often TypeScript had to correct AI output. High values for specific field patterns indicate systematic AI failures that may warrant prompt improvements.

**To monitor:**
```bash
# From a run log, count repairs by field:
grep CEO_PLAN_TRACE ceo-trace.log | \
  sed 's/.*CEO_PLAN_TRACE //' | \
  jq '.repairsApplied[]' | sort | uniq -c | sort -rn
```

Fields appearing frequently in `repairsApplied` are candidates for stronger CONTRATO instructions or Phase 2 extraction.
